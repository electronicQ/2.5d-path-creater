# LIGO 系统数据流向与处理流程图

### ⬇️ 第一阶段：传感器输入 (Sensor Inputs)
系统从 ROS 接收底层硬件的数据：
* **[ 📡 LiDAR 点云 ]** -> `(10Hz)`
* **[ ⏱️ IMU 数据 ]** -> `(200Hz)`
* **[ 🛰️ GNSS / RTK 数据 ]** -> `(10Hz)`

### ⬇️ 第二阶段：多传感器同步 (Time Synchronization)
**[ `src/laserMapping.cpp` ]**
* **作用**：作为主控节点，它将上述不同频率的传感器数据按时间戳对齐，打包放入各自的缓冲队列中，等待进一步处理。

### ⬇️ 第三阶段：前端局部定位 (LIO Frontend - 高频/相对位姿)
在这一步，LiDAR和IMU紧密结合，计算出平滑但随时间会产生累积漂移的局部轨迹。
* **IMU 预测 [ `src/IMU_Processing.cpp` ]**
    * `IMU 数据` ➡️ 进行前向积分 ➡️ 输出 **高频预测位姿** 并补偿激光点云的运动畸变。
* **点云预处理 [ `src/preprocess.cpp` ]**
    * `LiDAR 点云` ➡️ 降采样、特征提取（或直接使用点） ➡️ 输出 **去畸变点云**。
* **状态估计 [ `src/Estimator.cpp` & `IKFoM`库 ]**
    * 结合去畸变点云和预测位姿 ➡️ 利用迭代卡尔曼滤波与局部地图匹配 ➡️ 输出 **高精度的局部里程计先验**。

### ⬇️ 第四阶段：后端全局优化 (GNSS Backend - 低频/绝对位姿)
局部里程计的漂移在此阶段被消除，系统提供**两种可选的融合路径**来实现全局绝对定位：

* **路径 A：基于 GNSS 原始观测数据的紧耦合 [ `src/GNSS_Processing_fg.cpp` ]**
    * `卫星原始伪距/多普勒` ➡️ 滤除多径效应和非视距(NLOS)劣质卫星 ➡️ 转换为 **底层的伪距/多普勒绝对约束**（适用于城市峡谷等遮挡环境）。
* **路径 B：基于 NMEA 报文的松耦合 [ `src/NMEA_Processing_fg.cpp` ]**
    * `接收机直出的 NMEA 定位报文` ➡️ 解析经纬高坐标与置信度 ➡️ 转换为 **直接的 3D 绝对位置约束**（适用于直接拥有高质量 RTK 信号的场景）。

* **因子图优化 [ `Ceres Solver` ]**
    * 将 **[ 前端 LIO 的相对位姿先验 ]** 与 **[ 路径A 或 路径B 产生的绝对约束 ]** 放入同一个图中进行最小二乘优化 ➡️ 输出 **无漂移的全局绝对位姿**。

### ⬇️ 第五阶段：建图与结果输出 (Mapping & Output)
* **增量式建图 [ `include/ivox/` ]**
    * 利用优化后的绝对位姿，将当前帧点云插入到 **iVox 增量式体素地图** 中，实时更新全局地图。
* **结果发布 [ ROS Publishers ]**
    * ➡️ 发布 `Odometry` (定位输出)
    * ➡️ 发布 `Path` (全局轨迹)
    * ➡️ 发布 `PointCloud2` (供 Rviz 渲染的可视化点云地图)

---

### 💡 核心机制总结：
LIGO 的代码结构非常清晰，本质是一个**“前端局部高频 LIO + 后端全局低频 因子图优化”**的层次化融合框架（Hierarchy Fusion Framework）。

1.  **前端**追求**速度和短时间精度**（依靠 `IKFoM` 迭代卡尔曼滤波和 `iVox` 快速寻近邻）。
2.  **后端**追求**全局无漂移**（依靠 `Ceres` 因子图融合抗差处理过的 GNSS 数据）。
