# 阶段计划：未知区域与补洞策略

## 当前问题

当前点云转高程栅格地图后，原始 `elevation` 层中没有点云落入的栅格应为 `NaN`，表示未知区域。

如果在后续 `grid_map_demos/config/filters_demo_filter_chain_gai.yaml` 中进行补洞，补洞结果可能会把原始未知区域变成有效高程值。随后 `slope`、`roughness`、`edges`、`traversability` 等层会继续把这些区域计算成普通可通行区域，最终保存静态地图时就不会再得到未知灰度 `205`。

## 关于 observed_mask 恢复 NaN 的结论

如果在补洞前保存原始观测 mask：

```yaml
- name: observed_mask
  type: gridMapFilters/MathExpressionFilter
  params:
    output_layer: observed_mask
    expression: 0.0 * elevation + 1.0
```

则含义是：

- 原始 `elevation` 有点云的地方：`observed_mask = 1.0`
- 原始 `elevation` 是 `NaN` 的地方：`observed_mask = NaN`

如果在最终 `traversability` 阈值处理之后，再用该 mask 把未观测区域恢复为 `NaN`：

```yaml
- name: restore_unknown_to_nan
  type: gridMapFilters/ThresholdFilter
  params:
    condition_layer: observed_mask
    output_layer: traversability
    lower_threshold: 0.5
    set_to: .nan
```

那么只要某个栅格在原始 `elevation` 中是 `NaN`，最后都会被恢复成 `NaN`。

这包括：

1. 点云完全没扫过的大块未知区域。
2. 已扫到区域内部的小孔洞、稀疏漏扫格子。

因此，按这种做法，补洞只会影响中间计算，例如法向量、坡度、粗糙度、边缘；但最终 `traversability` 层里，原始 `NaN` 的格子仍然会被写回 `NaN`。

最终链路为：

```text
原始没点云区域
-> observed_mask = NaN
-> 中间可以被补洞参与计算
-> 最后 traversability 重新写回 NaN
-> toOccupancyGrid 自动变成 -1
-> save_continuous_map.py 保存成 205
```

## 阶段一：保守方案

如果目标是“只要原始没有点云落入这个格子，就一律禁止通行”，可以直接不做高程补洞。

推荐做法：

- 注释或移除 `create_global_mask`。
- 注释或移除 `strict_inpaint`。
- 后续计算尽量基于原始 `elevation`。
- 保留原始 `NaN`，让未知区域在保存静态地图时变为 `205`。

优点：

- 语义最清晰。
- 未知区域不会被误判为可通行。
- 符合路径规划“不进入未观测区域”的要求。

风险：

- 点云稀疏时，地图中可能出现大量 `205` 小斑点。
- 法向量、坡度、粗糙度等滤波器依赖邻域有效值，可能导致本来可走的区域也算不出 `traversability`。
- 全局路径可能被小孔洞切断。

## 阶段二：只补小洞方案

如果阶段一导致可通行区域过于破碎，再改成“只补小洞，不补大块未知区”。

目标语义：

```text
原始有点云区域：可信
原始有点云区域附近的小洞：可信，可以补
远离点云的大块未知区域：不可信，恢复 NaN
```

实现思路：

- 不要使用全地图 `global_mask`。
- 不要允许整张地图无条件补洞。
- 使用原始 `elevation` 或基于原始观测区域膨胀后的 mask 作为补洞范围。
- `fill_hole_radius` 设置小一些，例如 `0.4~0.8m`，只填局部扫描缝隙。
- 最终不要用原始 `observed_mask` 一刀切恢复，而应使用“补洞允许区域 mask”恢复未知区域。

阶段二的目标是允许小孔洞变成有效可通行区域，同时仍然禁止进入大块未观测区域。

## 当前建议

先执行阶段一，走保守方案：

```text
取消大范围补洞
保留 NaN
让未知区域保存为 205
```

如果后续发现静态地图中 205 小斑点太多，导致路径规划经常失败，再进入阶段二，实现“只补小洞”的可信区域补洞策略。
